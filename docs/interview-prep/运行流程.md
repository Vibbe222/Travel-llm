**如果你运行它，会一步步发生什么**

1. Python 进入 [run_fastapi.py](E:/BaiduNetdiskDownload/AI/langGraph_day01-day05/旅游规划机器人/run_fastapi.py:4)，调用 `uvicorn.run("api.main:app", host="127.0.0.1", port=8000, reload=True)`。
2. Uvicorn 开始导入 `api.main`，去拿 `app` 对象。
3. [api/main.py](E:/BaiduNetdiskDownload/AI/langGraph_day01-day05/旅游规划机器人/api/main.py:8) 会先导入 `chat_service`。  
4. [chat_service.py](E:/BaiduNetdiskDownload/AI/langGraph_day01-day05/旅游规划机器人/chat_service.py:15) 在导入时会做两件事：
   - 忽略一类 LangChain beta 警告
   - `load_dotenv(find_dotenv())`，把 `.env` 里的环境变量读进来  
   这一步只“加载”，不校验 key 是否可用。
5. 然后 [api/main.py](E:/BaiduNetdiskDownload/AI/langGraph_day01-day05/旅游规划机器人/api/main.py:13) 创建 `FastAPI(title="Travel Planner API")`，再挂上全开放的 CORS 中间件。
6. 同一个文件里注册 4 个接口：
   - `GET /`：返回 `templates/index.html`
   - `GET /health`：返回 `{"status":"ok"}`
   - `POST /sessions`：生成一个 `thread_id`
   - `POST /chat/stream`：流式聊天接口，返回 `application/x-ndjson`
7. 如果导入都成功，Uvicorn 服务就会启动完成。因为 `reload=True`，你还会有一个文件监听/重载机制；改动源码后它会自动重启子进程。

**启动完成后，但还没聊天时，服务处于什么状态**
这时 FastAPI 已经活了，但下面这些东西其实还没真正初始化：
- LangGraph `app`
- 大模型客户端
- Selenium Chrome 驱动
- DuckDuckGo 搜索
- 高德地图请求

也就是说，`/health` 和 `/sessions` 大概率能先正常工作；真正重的逻辑在 `/chat/stream` 第一次请求时才触发。

**第一次调用 `/chat/stream` 时会发生什么**
1. [api/main.py](E:/BaiduNetdiskDownload/AI/langGraph_day01-day05/旅游规划机器人/api/main.py:48) 收到 `thread_id`、`message`、`model_name`。
2. 它调用 [chat_service.py](E:/BaiduNetdiskDownload/AI/langGraph_day01-day05/旅游规划机器人/chat_service.py:25) 的 `build_config`，生成：
   - `configurable.thread_id`
   - `recursion_limit=60`
3. 然后返回一个 `StreamingResponse`，真正的数据源是 [iter_chat_event_lines](E:/BaiduNetdiskDownload/AI/langGraph_day01-day05/旅游规划机器人/chat_service.py:118)。
4. `iter_chat_event_lines` 内部继续调用 `iter_chat_events`。这里第一次会命中 [get_app](E:/BaiduNetdiskDownload/AI/langGraph_day01-day05/旅游规划机器人/chat_service.py:19)。
5. `get_app()` 是懒加载加缓存，会导入 `graph.graph` 并执行 `init_app(model_name)`。
6. [graph/graph.py](E:/BaiduNetdiskDownload/AI/langGraph_day01-day05/旅游规划机器人/graph/graph.py:8) 会创建 LangGraph：
   - 状态类型是 `PublicState`
   - 节点 1 是 `agent`
   - 节点 2 是 `tools`
   - 边是 `START -> agent -> (按条件去 tools 或结束)`，`tools -> agent`
7. 创建 `agent` 时会实例化 [AsyncAgent](E:/BaiduNetdiskDownload/AI/langGraph_day01-day05/旅游规划机器人/agents/agents.py:18)，它在构造函数里立刻调用 [QwenLLMFactory.get_llm](E:/BaiduNetdiskDownload/AI/langGraph_day01-day05/旅游规划机器人/models/qwen_factory.py:10)。
8. 这一步才真正检查 `DASHSCOPE_API_KEY`。如果没有，就会在这里抛 `ValueError`。
9. 如果 key 没问题，就创建一个 `ChatOpenAI` 客户端，但 `base_url` 指向 DashScope 兼容接口，默认模型是 `deepseek-v4-flash`。
10. 图编译时会创建 `InMemorySaver`，所以会话状态只保存在内存里；进程重启后就没了。
11. 真正开始处理用户消息时，`AsyncAgent.__call__` 会把提示词模板和“第一条用户消息”拼成首条 `HumanMessage`，再调用模型 `ainvoke(...)`。
12. 如果模型决定调用工具，LangGraph 会把流程导到 `ToolNode`，执行这些工具之一：
   - `web_search`
   - `get_location_coordinate`
   - `get_attractions_information`
   - `route_planning`
   - `search_nearby_poi`
   - `save_info_and_clear_history`
13. [chat_service.py](E:/BaiduNetdiskDownload/AI/langGraph_day01-day05/旅游规划机器人/chat_service.py:41) 会把 LangGraph 事件规范化成前端流：
   - 模型流式 token -> `{"type":"chunk","content":"..."}`
   - 工具开始 -> `tool_start`
   - 工具结束 -> `tool_end`
   - 最后补一个 `{"type":"done"}`
14. 如果过程中有异常，不会直接炸 HTTP 连接，而是流里给你一条 `{"type":"error", ...}`。

打开网页后，到用户问完一个问题，整个流程可以按“前端一条线 + 后端一条线”来看。

**整体流程**

1. 浏览器先访问 GET /。
    FastAPI 在 api/main.py (line 43) 把 templates/index.html 返回给浏览器，所以聊天页面先显示出来。

2. 页面初始化时，前端会先创建会话。
    在 templates/index.html (line 402) 它会请求 POST /sessions。
    后端在 api/main.py (line 53) 处理这个请求，调用 create_session()，生成一个 thread_id 返回给前端。这个 thread_id 相当于“这轮对话的会话编号”。

3. 用户在输入框里输入问题，点击发送。
    前端会把：

   - thread_id
   - message
   - model_name

   发到 POST /chat/stream，代码在 templates/index.html (line 435)。

4. FastAPI 收到聊天请求。
    后端入口在 api/main.py (line 59)。
    这里先调用 chat_service.py 里的 build_config() 组装本次运行配置，把 thread_id 放进去，方便记住上下文。

5. 后端开始“流式”处理，而不是一次性等全部结果。
    POST /chat/stream 返回的是 StreamingResponse，数据来源是 iter_chat_event_lines(...)。
    也就是说，后端会一边生成内容，一边把结果一点点推给前端，而不是整段答案生成完再返回。

6. 第一次聊天时，会懒加载 LangGraph 应用。
    在 chat_service.py 里，get_app() 会导入 graph.graph，执行 init_app(model_name)。
    这一步会创建图、初始化 Agent、准备工具节点。

7. 创建 Agent 时，会真正初始化大模型客户端。
    AsyncAgent 构造时会调用 models/qwen_factory.py (line 15) 的 os.getenv("DASHSCOPE_API_KEY")。
    这时才真正检查环境变量有没有配好。没配就会报错。

8. 模型开始处理用户问题。
    Agent 会把“系统提示词 + 用户这次消息”拼起来，调用模型。
    如果模型只需要直接回答，就持续输出文本。
    如果模型判断要查景点、路线、坐标之类，就会调用工具。

9. 工具调用时，LangGraph 会在 agent 和 tools 节点之间流转。
    例如可能会调用：

   - web_search
   - get_location_coordinate
   - route_planning
   - search_nearby_poi

1. 后端把这些过程包装成前端能消费的事件流。
    在 chat_service.py 里会把事件规范成：
   - chunk：模型输出的一小段文字
   - tool_start：工具开始
   - tool_end：工具结束
   - done：本次回答结束
   - error：中途异常
2. 前端一边读流，一边更新页面。
    所以你会看到：
   - 回答不是一下子整段出来，而是逐字/逐段出现
   - 如果用了工具，调试区可能会显示工具开始和结束
   - 最终生成完整回答并渲染到聊天窗口

**你可以把它记成一句话**

用户发消息后，流程就是：

前端 fetch /chat/stream -> FastAPI 接口 -> chat_service -> LangGraph app -> 大模型/工具 -> 流式事件返回前端 -> 页面实时显示答案

**补一个很实用的理解**

- GET / 是“打开页面”
- POST /sessions 是“领一个会话号”
- POST /chat/stream 是“真正开始聊天”
- LangGraph 和模型初始化，主要发生在第一次真正聊天时，不是在服务刚启动时全部做完
