# 第二阶段优化技术方案

## 背景与目标

第一阶段已经完成工具层稳定性改造，外部工具统一返回 `success / data / error` 结构，并对高德、DuckDuckGo、马蜂窝 Selenium 抓取等外部依赖做了超时、重试、业务错误和降级处理。

第二阶段的目标是在不调用真实外部服务的前提下，先把最容易发生回归的工具层和基础 API 入口保护起来。后续修改工具实现、Prompt 或接口结构时，可以通过测试快速发现返回协议、异常处理和基础请求结构是否被破坏。

## 本阶段范围

本阶段正式优化对象：

- 新增并扩展 `tests/` 测试套件；
- 覆盖 `tools/base.py` 的统一返回和 HTTP 重试封装；
- 覆盖高德相关工具：
  - `tools/locations.py`
  - `tools/nearby.py`
  - `tools/transportation.py`
- 覆盖 DuckDuckGo 搜索工具：
  - `tools/web_search.py`
- 覆盖马蜂窝景点抓取和降级逻辑：
  - `tools/attractions.py`
- 新增 FastAPI 冒烟测试：
  - `/health`
  - `/sessions`
  - `/chat/stream`
- 将 `pytest` 明确加入 `requirements.txt`，保证新环境可以直接安装测试依赖。

## 不做事项

本阶段不做以下事项：

- 不调用真实高德 API；
- 不调用真实 DuckDuckGo 网络搜索；
- 不启动真实 Chrome / Selenium 浏览器；
- 不测试真实大模型调用；
- 不重构 LangGraph 流程；
- 不修改 `/chat/stream` 返回协议；
- 不改造前端 UI；
- 不引入覆盖率门槛；
- 不新增 CI 流程。

## 测试设计原则

### 1. 外部依赖全部 mock

测试必须稳定、快速、可重复，不依赖网络、API key、浏览器或第三方服务状态。

mock 对象包括：

- `requests.get`；
- `request_json_with_retry(...)`；
- `DDGS`；
- Selenium driver；
- 马蜂窝页面 HTML；
- `create_session(...)`；
- `build_config(...)`；
- `iter_chat_event_lines(...)`。

### 2. 优先覆盖行为契约

测试重点不是验证第三方返回格式是否永远不变，而是验证本项目对外部异常的处理契约是否稳定：

- 成功时返回 `success=True`；
- 失败时返回 `success=False`；
- 失败必须包含 `error.message`；
- 可重试错误标记 `retryable=True`；
- 业务错误、空结果、缺少环境变量标记 `retryable=False`；
- 工具层不向外抛出可预期的外部依赖异常。

### 3. API 冒烟测试只验证接口骨架

`/chat/stream` 不在本阶段测试真实模型输出，只验证：

- 请求体字段结构可被 FastAPI 接收；
- `thread_id` 能传入 `build_config(...)`；
- `message` 和 `model_name` 能传入流式生成器；
- 响应类型为 `application/x-ndjson`；
- 缺少必要字段时返回 `422`。

## 工具层覆盖方案

### `tests/test_tools_base.py`

覆盖目标：统一返回结构和 HTTP JSON 请求封装。

覆盖场景：

- `ok(...)` 返回成功结构；
- `fail(...)` 返回失败结构；
- HTTP 500 首次失败后重试成功；
- HTTP 400 不重试，直接返回不可重试错误；
- 网络超时按配置重试，最终返回 `http_request_timeout`；
- 非 JSON 响应返回 `invalid_json_response`。

### `tests/test_tools_locations.py`

覆盖目标：地点坐标工具。

覆盖场景：

- 缺少 `AMAP_API_KEY`；
- 高德成功返回坐标；
- 高德业务错误；
- 高德空 geocodes；
- 下层 HTTP 超时失败透传。

### `tests/test_tools_nearby.py`

覆盖目标：周边 POI 搜索工具。

覆盖场景：

- 关键字和类型都为空；
- 缺少 `AMAP_API_KEY`；
- 高德成功返回 POI；
- 高德业务错误；
- 高德返回空 POI；
- 下层 HTTP 超时失败透传。

### `tests/test_tools_transportation.py`

覆盖目标：路线规划工具。

覆盖场景：

- 缺少 `AMAP_API_KEY`；
- 成功返回但无公共交通方案时给出 warning；
- 高德业务错误；
- 高德响应结构缺少 `route`；
- 下层 HTTP 超时失败透传。

### `tests/test_tools_web_search.py`

覆盖目标：DuckDuckGo 搜索工具。

覆盖场景：

- 搜索成功；
- 搜索结果为空；
- 搜索超时重试 3 次后返回 `web_search_timeout`。

### `tests/test_tools_attractions.py`

覆盖目标：马蜂窝景点抓取和降级逻辑。

覆盖场景：

- Selenium 失败后降级到 `web_search`；
- 景点数量上限为 5；
- 使用 mock HTML 成功解析马蜂窝目的地、景点详情、建议游玩时长和开放时间；
- Selenium 失败且 fallback 搜索也失败时，返回明确的 `attractions_fallback_failed`。

## API 冒烟测试方案

新增文件：

- `tests/test_api_smoke.py`

覆盖接口：

### `/health`

期望：

```json
{"status": "ok"}
```

### `/sessions`

mock `create_session(...)`，只验证接口返回：

```json
{"thread_id": "test-thread"}
```

### `/chat/stream`

mock `build_config(...)` 和 `iter_chat_event_lines(...)`，验证：

- 请求体包含 `thread_id`、`message`、`model_name`；
- 接口返回 NDJSON；
- 基础流式响应可被 TestClient 消费；
- 缺少必填字段时返回 `422`。

## 实施顺序

1. 确认第一阶段测试可以通过。
2. 扩展工具层测试，补齐超时、空结果、缺少环境变量和业务错误。
3. 新增 API 冒烟测试。
4. 将 `pytest` 加入 `requirements.txt`。
5. 运行完整测试套件。
6. 编写第二阶段技术方案和验收文档。

## 验收标准

第二阶段完成后，应满足以下标准：

- 存在可运行的 `tests/` 测试套件；
- 工具层成功、API 错误、网络超时、空结果、缺少环境变量都有测试保护；
- 高德、DuckDuckGo、马蜂窝相关外部响应全部通过 mock 模拟；
- 测试不依赖真实网络、真实 API key、真实浏览器；
- `/health` 有冒烟测试；
- `/sessions` 有冒烟测试；
- `/chat/stream` 基础请求结构有冒烟测试；
- `pytest` 作为项目依赖被明确记录；
- 完整测试套件本地通过。

## 风险与注意事项

1. 当前测试重点是工具层和接口骨架，不能替代真实外部 API 联调。
2. mock HTML 只能保护当前解析逻辑，不能保证马蜂窝真实页面结构长期稳定。
3. `/chat/stream` 当前只测请求结构和 NDJSON 输出，不测真实 LangGraph、大模型或工具链完整执行。
4. 后续如果引入会话持久化、鉴权或前端协议变化，需要补充 API 层更完整的集成测试。
5. 如果后续区分生产依赖和开发依赖，建议将 `pytest` 移入单独的 `requirements-dev.txt` 或 `pyproject.toml` 的 dev 依赖组。
