# 第七阶段优化技术方案

## 背景与目标

第六阶段已经完成 Redis 缓存与会话持久化，后端在外部服务不可用时具备一定降级能力。但前端仍存在几个体验问题：

- 用户发起长任务后，早期缺少明确反馈；
- 工具调用、失败原因和降级状态主要停留在调试日志里；
- 用户无法主动停止长时间生成；
- 会话创建、历史会话和导出能力不够清晰；
- 工具失败时，普通用户看到的信息和开发调试信息没有分层；
- fallback、缓存旧数据、跳过失败工具等降级行为没有独立提示。

第七阶段目标是让用户更容易理解生成过程和失败原因，让前端从演示页面接近可用产品。

## 本阶段范围

本阶段优化对象：

- `chat_service.py`
- `templates/index.html`
- `tests/test_streaming_and_prompts.py`

本阶段不引入新的前端构建系统，继续使用当前 FastAPI + Vue CDN + 单页 HTML 的轻量结构。

## 不做事项

本阶段不做以下事项：

- 不引入 React、Vite、Webpack 等前端工程化体系；
- 不新增数据库表保存历史会话；
- 不改造 LangGraph 节点拓扑；
- 不暴露内部 Prompt、模型中间推理或 API 密钥；
- 不把工具原始返回直接展示给普通用户；
- 不实现用户账号体系；
- 不实现服务端历史会话列表接口；
- 不修改外部工具统一返回协议。

## 后端事件协议设计

`/chat/stream` 继续使用 NDJSON：

```text
application/x-ndjson
```

每一行是一个独立 JSON 事件，前端读取一行就处理一行。

第七阶段新增或增强以下事件类型：

| 事件类型 | 用途 |
|---|---|
| `progress` | 用户可见进度 |
| `degradation` | 降级提示 |
| `tool_error` | 工具失败分层信息 |
| `error` | 后端异常分层信息 |
| `chunk` | 最终回复文本片段 |
| `tool_start` | 工具开始调用 |
| `tool_end` | 工具调用结束 |
| `done` | 本次生成完成 |

## progress 事件设计

请求开始后，后端尽快输出首条进度：

```json
{
  "type": "progress",
  "stage": "request",
  "message": "已收到请求，正在准备生成"
}
```

LangGraph 节点开始和结束时，输出用户可理解的阶段状态：

| 节点 | 开始文案 | 完成文案 |
|---|---|---|
| `intent_router` | 正在理解旅行需求 | 已识别旅行需求 |
| `destination_clarifier` | 正在补全目的地信息 | 已整理目的地候选 |
| `attraction_collector` | 正在获取景点信息 | 已获取景点信息 |
| `itinerary_planner` | 正在生成行程草案 | 已生成行程草案 |
| `transport_validator` | 正在校验交通可行性 | 已完成交通校验 |
| `poi_enricher` | 正在补充餐饮和住宿建议 | 已补充周边推荐 |
| `final_responder` | 正在整理最终回复 | 已生成最终回复 |

设计原则：

- 只展示用户能理解的状态；
- 不展示 Prompt；
- 不展示 JSON 中间过程；
- 不展示模型思考或内部链路细节；
- 最终回复到达后，进度归档在助手消息内的“生成过程”区域。

## 停止生成设计

前端使用 `AbortController` 实现主动停止：

```text
用户点击“停止生成”
  -> abort 当前 fetch
  -> 前端标记当前助手消息为“已停止”
  -> 保留已生成内容和已有进度
  -> 恢复输入框可用状态
```

说明：

- 浏览器会中断当前 HTTP 流读取；
- 后端任务是否能完全取消取决于底层执行框架和外部工具调用状态；
- 用户侧体验上会立即停止继续接收内容。

## 新建会话与历史会话设计

新增“新建会话”按钮：

```text
点击新建会话
  -> 如当前正在生成，先停止生成
  -> POST /sessions
  -> 获得新的 thread_id
  -> 清空当前消息和调试日志
  -> 写入本地历史会话列表
```

历史会话暂存在浏览器 `localStorage`：

```text
travelPlannerSessions:v1
```

保存内容：

- `threadId`
- 会话标题；
- 更新时间；
- 消息列表；
- 工具调试日志；
- 生成过程；
- 降级提示；
- 错误提示。

本阶段选择浏览器本地历史，是为了避免引入后端数据库和用户体系。

## 工具调用面板折叠设计

右侧“工具调用面板”支持折叠：

- 默认展示工具调用日志；
- 用户可点击“折叠”隐藏详细日志；
- 折叠状态只影响当前页面展示；
- 工具日志仍会持续记录，用于导出和调试。

工具面板主要面向开发和排查，不作为普通用户理解结果的主入口。

## 错误信息分层展示

工具失败或后端异常时，前端展示三层信息：

### 1. 用户可读错误

示例：

```text
外部数据服务响应超时，当前结果可能不完整。
```

特点：

- 简短；
- 可理解；
- 不包含堆栈；
- 不包含密钥或内部 Prompt。

### 2. 调试详情

示例：

```json
{
  "tool": "route_planning",
  "error_type": "http_request_timeout",
  "retryable": true,
  "detail": "slow upstream"
}
```

特点：

- 默认折叠；
- 给开发者排查；
- 不直接打断用户阅读主结果。

### 3. 工具原始返回

原始返回只在调试展开区展示，并经过 JSON 安全清洗。

敏感字段会被替换：

```text
[已隐藏]
```

当前清洗字段包括：

- `api_key`
- `apikey`
- `key`
- `token`
- `authorization`
- `password`
- `secret`
- `prompt`
- `state_summary`
- `messages`

## 降级提示框设计

当系统发生以下情况时，前端展示独立“降级提示”：

- 使用 fallback；
- 使用缓存旧数据；
- 跳过失败工具；
- 改用规则生成；
- 采用不完整数据；
- 外部工具返回 warning。

展示内容：

- 降级原因；
- 影响范围；
- 当前结果可信度；
- 调试模式下的阶段、工具名、错误类型和原始错误摘要。

示例：

```text
降级提示
原因：主数据源不可用，已改用备用数据来源。
影响：景点详情、开放时间或停留时长可能不如主数据源完整。
可信度：中等
```

设计原则：

- 不打断主流程；
- 必须明显可见；
- 不把降级结果伪装成正常结果；
- 不暴露内部 Prompt、JSON 中间推理或 API 密钥。

## 导出功能设计

新增两个导出入口：

| 按钮 | 功能 |
|---|---|
| 导出当前 | 导出当前会话 |
| 导出历史 | 导出本地保存的全部历史会话 |

导出格式：

```text
Markdown
```

导出内容包括：

- Thread ID；
- 导出时间；
- 用户消息；
- 助手回复；
- 生成过程；
- 降级提示；
- 错误提示；
- 工具调试日志。

## 前端布局设计

第七阶段将页面调整为三栏工作区：

```text
顶部栏：标题、状态、新建会话、导出
左侧栏：历史会话
中间栏：聊天对话和输入框
右侧栏：生成过程和工具调用面板
```

移动端时布局自动折叠为单列。

视觉原则：

- 控制台式产品界面；
- 信息密度适中；
- 避免装饰性过强；
- 卡片圆角控制在 8px；
- 进度、错误、降级用不同背景和边框区分。

## 实施顺序

1. 在 `chat_service.py` 中定义节点进度文案。
2. 将 `on_chain_start` / `on_chain_end` 转为 `progress` 事件。
3. 请求开始后立即输出首条 `progress`。
4. 将工具 fallback、warning、缓存提示转为 `degradation` 事件。
5. 将工具失败转为 `tool_error` 事件。
6. 后端异常改为用户错误、调试详情、原始信息分层输出。
7. 对事件输出执行 JSON 安全清洗，隐藏敏感字段。
8. 重做 `templates/index.html` 页面结构。
9. 增加“停止生成”按钮和 `AbortController`。
10. 增加“新建会话”和本地历史会话。
11. 增加工具调用面板折叠。
12. 增加进度、降级、错误展示区域。
13. 增加当前会话和历史会话 Markdown 导出。
14. 补充流式事件测试。
15. 运行完整测试套件和本地 FastAPI smoke 验证。

## 验收标准

第七阶段完成后，应满足以下标准：

- 用户能主动中断长时间生成；
- 页面提供“新建会话”入口；
- 当前浏览器支持历史会话切换；
- 工具调用面板支持折叠；
- 请求开始后尽快返回首条进度；
- 每个关键节点输出用户可读进度；
- 进度不暴露内部 Prompt、JSON、模型中间推理或 API 密钥；
- 最终回复和进度能够在同一助手消息中自然归档；
- 工具失败时分层展示用户错误、调试详情和原始返回；
- fallback、缓存旧数据、不完整数据等情况使用独立降级提示框；
- 降级提示说明原因、影响范围和可信度；
- 调试模式下可查看阶段、工具名、错误类型和摘要；
- 当前会话可以导出；
- 历史会话可以导出；
- 完整测试套件通过。

## 风险与注意事项

1. 当前历史会话保存在浏览器 `localStorage`，换浏览器或清理缓存后会丢失。
2. 停止生成是前端中断 HTTP 流，不能保证已经进入外部工具的后端调用立即停止。
3. 降级事件依赖工具返回中包含 `fallback_used`、`warnings`、`cache_used`、`stale_cache_used` 等字段；如果未来工具新增降级类型，需要同步扩展事件识别逻辑。
4. 工具原始返回虽然会清洗敏感字段，但后续新增敏感字段名时仍需维护清洗列表。
5. 本阶段没有引入服务端历史会话管理，因此多设备同步不在范围内。
