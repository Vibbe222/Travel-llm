### 3. 停止生成

实现方式：

- 前端使用 `AbortController`；
- 点击“停止生成”后中断当前 `fetch` 流读取；
- 当前助手消息标记为“已停止”；
- 保留已生成内容；
- 恢复输入状态。

当前用户侧行为：

```text
正在生成 -> 点击停止生成 -> 不再继续追加新内容 -> 当前消息显示已停止
```

### 4. 新建会话与历史会话

实现方式：

- 新建会话调用 `POST /sessions`；
- 获取新的 `thread_id`；
- 清空当前消息和工具日志；
- 当前浏览器通过 `localStorage` 保存最近历史会话。

本地存储 key：

```text
travelPlannerSessions:v1
```

### 6. 错误分层展示

工具失败时，前端展示：

1. 用户可读错误；
2. 调试详情；
3. 工具原始返回。

示例结构：

```json
{
  "type": "tool_error",
  "tool": "route_planning",
  "user_message": "外部数据服务响应超时，当前结果可能不完整。",
  "debug": {
    "tool": "route_planning",
    "error_type": "http_request_timeout",
    "retryable": true,
    "detail": "slow upstream"
  },
  "raw": {}
}
```

## 当前行为说明

### 正常生成时

- 用户发送消息；
- 前端立即显示“已发送请求，等待服务端响应”；
- 后端返回“已收到请求，正在准备生成”；
- 每个关键节点追加进度；
- 最终回复以流式文本追加；
- 完成后显示“生成完成”。

### 工具失败时

- 主流程尽量继续；
- 前端展示用户可读错误；
- 调试详情默认折叠；
- 工具原始返回只在展开后查看。

### 发生 fallback 时

- 主流程继续；
- 前端展示独立降级提示；
- 降级提示说明原因、影响和可信度；
- 调试区可查看工具名、阶段和错误类型。

### 用户停止生成时

- 当前 HTTP 流被中断；
- 当前助手消息停止追加；
- 已生成内容保留；
- 输入框恢复可用。

## 遗留事项

1. 历史会话目前只保存在浏览器本地。

   后续如需多设备同步或服务端查询历史，需要增加服务端会话存储接口。

2. 停止生成目前是前端中断流读取。

   如果要让后端任务也强制取消，需要进一步设计任务注册表、取消标记和 LangGraph 执行取消机制。

3. 降级事件依赖工具返回结构。

   后续如果新增更多工具或更多降级类型，需要统一定义工具降级元数据字段。

4. 工具调用日志仍偏开发视角。

   后续可以进一步把工具日志聚合成用户更容易理解的“数据来源摘要”。
