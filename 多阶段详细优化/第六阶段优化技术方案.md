# 第六阶段优化技术方案

## 背景与目标

第五阶段已经完成统一配置与安全收口，模型、API key、CORS、超时、日志等运行参数都能通过 `settings.py` 统一读取。第六阶段在此基础上引入 Redis，用于减少重复外部请求，并让 LangGraph 会话状态具备跨进程重启恢复能力。

当前项目中重复成本最高的部分主要集中在：地点坐标、景点抓取、周边 POI、路线规划和网络搜索。这些结果天然适合 TTL 缓存。同时，原有 LangGraph 使用 `InMemorySaver`，服务重启后会话状态会丢失，需要替换为可持久化方案。

本阶段选择连接本地 Docker Redis，并参考 `E:\py_project\JD_RMS_LLM` 的 Redis 降级思路：Redis 懒连接，连接失败或依赖缺失时不阻塞主流程，而是回退到无缓存或内存 checkpointer。

## 不做事项

本阶段不做以下事项：

- 不引入 Postgres 或 SQLite checkpointer；
- 不要求 Redis 必须启动才能运行项目；
- 不缓存失败结果；
- 不改变工具统一返回协议；
- 不改变 `/chat/stream` 协议；
- 不改造前端展示缓存命中状态；
- 不做分布式锁；
- 不实现 Redis 集群或哨兵配置；
- 不实现复杂缓存失效后台任务。

## Redis 配置设计

在 `settings.py` 中新增 Redis 相关配置：

| 字段 | 环境变量 | 默认值 | 说明 |
|---|---|---|---|
| `cache_enabled` | `CACHE_ENABLED` | `true` | 是否启用 Redis TTL 缓存 |
| `cache_ttl_seconds` | `CACHE_TTL_SECONDS` | `86400` | 工具查询缓存 TTL，默认 1 天 |
| `redis_url` | `REDIS_URL` | `redis://127.0.0.1:6379/0` | Redis 连接地址 |
| `redis_key_prefix` | `REDIS_KEY_PREFIX` | `travel_llm` | Redis key 前缀 |
| `redis_checkpoint_enabled` | `REDIS_CHECKPOINT_ENABLED` | `true` | 是否启用 Redis checkpointer |
| `redis_checkpoint_ttl_seconds` | `REDIS_CHECKPOINT_TTL_SECONDS` | `604800` | 会话 checkpoint TTL，默认 7 天 |

`.env.example` 同步补充：

```env
CACHE_ENABLED=true
CACHE_TTL_SECONDS=86400
REDIS_URL=redis://127.0.0.1:6379/0
REDIS_KEY_PREFIX=travel_llm
REDIS_CHECKPOINT_ENABLED=true
REDIS_CHECKPOINT_TTL_SECONDS=604800
```

## Redis 依赖

`requirements.txt` 新增：

```text

```

Redis 客户端在代码中仍采用懒加载：

- 如果 `redis` 包未安装，缓存自动禁用；
- 如果 Redis 服务不可用，缓存自动禁用；
- 如果 Redis 读写失败，记录 warning，并继续使用正常外部请求或内存状态。

## TTL 缓存设计

新增 `utils/redis_cache.py`，提供：

- `RedisCacheService`
- `redis_cache`
- `make_cache_key(namespace, payload)`

### Cache key 设计

缓存 key 格式：

```text
{REDIS_KEY_PREFIX}:cache:{namespace}:{sha256(payload)}
```

其中 `payload` 会先进行 JSON 安全序列化，并按 key 排序，确保同样参数生成同样 cache key。

示例：

```python
make_cache_key("location_coordinate", {"location": "三坊七巷", "city": "福州"})
```

会生成类似：

```text
travel_llm:cache:location_coordinate:<hash>
```

### 缓存服务降级

`RedisCacheService` 行为：

1. 首次使用时才连接 Redis；
2. 连接成功后复用 client；
3. 连接失败时 `_client=None`，后续 `get_json` 返回 `None`；
4. `set_json` 在 Redis 不可用时直接 no-op；
5. Redis 读写异常只记录 warning，不影响主流程。

## 接入缓存的查询

本阶段接入五类查询：

| 查询 | 文件 | namespace |
|---|---|---|
| 地点坐标 | `tools/locations.py` | `location_coordinate` |
| 景点信息 | `tools/attractions.py` | `attractions` |
| 周边 POI | `tools/nearby.py` | `nearby_poi` |
| 交通路线 | `tools/transportation.py` | `route_planning` |
| 搜索结果 | `tools/web_search.py` | `web_search` |

通用流程：

```text
构造 cache key
  -> Redis get
  -> 命中：直接返回缓存结果
  -> 未命中：执行原外部请求
  -> 成功：写入 Redis TTL 缓存
  -> 失败：不缓存
```

设计原则：

- 只缓存成功结果；
- 不缓存外部 API 失败、空结果、参数错误和网络超时；
- 缓存内容保持原工具返回结构；
- Redis 不可用时行为等同未接入缓存。

## LangGraph Checkpointer 设计

原实现：

```python
from langgraph.checkpoint.memory import InMemorySaver

memory = InMemorySaver()
return graph.compile(checkpointer=memory)
```

新实现：

```python
from graph.checkpoint import build_checkpointer

return graph.compile(checkpointer=build_checkpointer())
```

新增 `graph/checkpoint.py`：

- `RedisBackedMemorySaver`
- `build_checkpointer()`

### RedisBackedMemorySaver

当前环境没有安装官方 `langgraph-checkpoint-redis` 包，因此本阶段实现了一个兼容 `InMemorySaver` 的 Redis-backed 适配器：

- 继承 `InMemorySaver`；
- 启动时从 Redis 读取已保存 snapshot；
- 每次 `put`、`put_writes`、`delete_thread` 后将内存 snapshot 写回 Redis；
- Redis 写失败时继续在内存中运行；
- Redis key：

```text
{REDIS_KEY_PREFIX}:checkpoints:v1
```

这种方案优先保证本地演示和重启恢复能力，同时保持与当前 LangGraph 版本兼容。

### Checkpointer 降级策略

`build_checkpointer()` 流程：

```text
REDIS_CHECKPOINT_ENABLED=false
  -> InMemorySaver

redis 包未安装
  -> InMemorySaver

Redis ping 失败
  -> InMemorySaver

Redis 可用
  -> RedisBackedMemorySaver
```

因此 Redis 未启动时，服务仍能正常运行，只是会话状态回退为进程内存。

## 风险与注意事项

1. 当前 Redis-backed checkpointer 是基于 `InMemorySaver` snapshot 的项目内适配器，适合本地演示和轻量持久化。若未来进入生产部署，建议评估官方 Redis/Postgres checkpointer 包。
2. Checkpoint 当前保存为一个 Redis key 下的整体 snapshot，极大规模会话时需要拆分 key 或使用官方存储实现。
3. TTL 缓存只缓存成功结果，不缓存失败结果。这样可以避免临时故障被长期保存，但相同失败请求仍可能重复访问外部服务。
4. Redis 在线时测试可能受到历史缓存影响，因此测试中使用独立 `REDIS_KEY_PREFIX` 隔离。
5. `CACHE_ENABLED=false` 只会关闭查询缓存，不会关闭 checkpointer；checkpointer 由 `REDIS_CHECKPOINT_ENABLED` 单独控制。
