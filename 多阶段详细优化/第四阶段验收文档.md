## 当前行为说明

### 1. 意图识别失败时

当 `intent_router` 的模型输出不是合法 JSON 时：

- `StageExecutor` 调用 `_fallback_intent_result(state)`；
- fallback 从用户最新消息中用规则推断意图；
- 尝试提取目的地和基础约束；
- 返回结构化字段；
- 流程继续向后执行。

### 2. 行程规划失败时

当 `itinerary_planner` 的模型输出不是合法 JSON 时：

- `StageExecutor` 调用 `_fallback_plan_result(state)`；
- fallback 使用 `_build_fallback_daily_plan(...)` 生成基础 `daily_plan`；
- 流程继续进入交通校验；
- 最终回复可说明过程中存在降级或校验提示。

### 3. 非 JSON 节点失败时

`clarify`、`validation` 和 `finalize` 当前不强制 JSON。

它们的失败路径仍按原逻辑处理：

- 模型调用异常时，若提供 fallback，则进入 fallback；
- 没有 fallback 时返回空内容和错误信息；
- 核心流程不依赖这些节点的模型文本完成结构化状态沉淀。

## 遗留事项

1. JSON schema 尚未强类型化。

   当前依赖 Prompt 描述和 Python fallback 保证结构稳定。后续可以引入 Pydantic 模型校验 `intent` 和 `daily_plan`。

2. `safe_json_loads` 仍是轻量解析器。

   当前只处理标准 JSON 和简单 fenced code block。后续如果模型经常返回前后夹杂解释文字，可以考虑增加更严格的提取策略，但不建议做过度猜测。

3. 交通校验 Prompt 暂未结构化。

   当前交通风险主要由规则判断。后续如果希望模型补充开放时间、跨城合理性、行程密度等问题，可以让 `validation.py` 输出 JSON 格式的 `issues`。

4. 最终回复仍是 Markdown 文本。

   这适合当前聊天界面。如果后续前端需要卡片化展示，可新增结构化最终结果字段，再由前端渲染。

5. 旧 `Agent` 类仍存在。

   当前正式入口不依赖旧 `agent_prompt_template`。如果后续彻底清理旧 Agent 代码，需要单独评估 `agents/agents.py` 是否还有保留价值。
