# 第一阶段优化技术方案

## 背景与目标

当前旅游规划机器人已经具备基础的 LangGraph 编排、FastAPI 流式接口和多个外部工具能力，但工具层仍存在返回格式不统一、外部请求失败不可控、日志不规范、Selenium 抓取不稳定、缺少工具层测试等问题。

第一阶段的目标是先稳定工具层，让所有外部依赖调用可控、可恢复、可观测、可测试，为后续结构化状态、多节点 LangGraph 重构和产品化部署打基础。

## 本阶段范围

本阶段正式优化对象：

- `tools/locations.py`
- `tools/nearby.py`
- `tools/transportation.py`
- `tools/web_search.py`
- `tools/attractions.py`
- 新增 `tools/base.py`
- 少量调整 `prompts/main.py`
- 新增 `tests/` 下的工具层测试

当前正式入口仍以 `graph/graph.py + tools/` 为主。

## 不做事项

本阶段不做以下事项：

- 不修改 `new/` 目录；
- 不兼容 `new/tools/`；
- 不重构 LangGraph 多节点流程；
- 不引入会话持久化；
- 不改造前端 UI；
- 不改变 `/chat/stream` 的事件格式；
- 不调用真实外部 API 做测试；
- 不把 `pytest` 强制加入 `requirements.txt`；
- 不处理非外部工具稳定性相关的拼写和代码风格问题，例如 `infomation_to_save`。

说明：`new/` 目录当时只作为参考资料，第一阶段不投入兼容成本；该目录已在第三阶段迁移完成后删除。

## 统一返回协议

所有外部工具统一返回如下结构。

成功时：

```python
{
    "success": True,
    "data": {},
    "error": None,
}
```

失败时：

```python
{
    "success": False,
    "data": None,
    "error": {
        "message": "amap_request_timeout",
        "detail": "请求高德接口超时",
        "retryable": True,
    },
}
```

字段说明：

- `success`: 是否成功拿到可用结果。
- `data`: 成功时的业务数据；失败时为 `None`。
- `error`: 失败信息；成功时为 `None`。
- `error.message`: 机器可读错误码，便于测试、日志和后续 Agent 判断。
- `error.detail`: 人类可读错误详情。
- `error.retryable`: 当前失败是否具备重试意义。

成功结果允许在 `data` 中加入元信息：

```python
{
    "source": "amap",
    "fallback_used": False,
    "warnings": [],
}
```

Selenium 降级时示例：

```python
{
    "success": True,
    "data": {
        "source": "web_search_fallback",
        "fallback_used": True,
        "overview": "因景点页面抓取失败，已使用网页搜索结果降级生成。",
        "scenic_list": []
    },
    "error": None,
}
```

## 异常处理原则

业务失败和外部依赖失败不抛异常，只返回失败结构。

这类失败包括：

- 缺少环境变量；
- HTTP 超时；
- 连接失败；
- 第三方接口返回业务错误；
- 第三方接口返回空结果；
- JSON 解析失败；
- Selenium 页面加载失败；
- 页面结构变化导致目标元素不存在。

真正的编程错误继续抛异常。

这类错误包括：

- 函数调用参数类型明显错误；
- 代码属性名写错；
- 未定义变量；
- 不应被吞掉的内部逻辑错误。

## 公共模块设计

新增 `tools/base.py`，放置工具层公共能力。

建议包含：

```python
def ok(data):
    return {
        "success": True,
        "data": data,
        "error": None,
    }


def fail(message, detail=None, retryable=False):
    return {
        "success": False,
        "data": None,
        "error": {
            "message": message,
            "detail": detail,
            "retryable": retryable,
        },
    }
```

同时建议加入：

- `get_tool_logger(name: str)`：创建工具日志对象；
- `configure_logging_from_env()`：根据 `LOG_LEVEL` 初始化日志；
- `summarize_params(params: dict)`：生成低风险入参摘要；
- `request_json_with_retry(...)`：统一 HTTP JSON 请求和重试逻辑；
- `is_retryable_http_status(status_code: int)`：判断临时服务错误；
- `safe_json(response)`：安全解析 JSON。

## 超时与重试策略

默认外部 HTTP 工具超时时间为 `12s`。

默认重试策略：

- 高德相关 HTTP 工具重试 2 次；
- `web_search` 保留 3 次；
- 只重试网络错误、连接错误、超时、临时服务错误；
- 不重试业务错误；
- 不重试空结果；
- 不重试参数错误；
- 不重试缺少环境变量。

建议重试的异常或状态：

- `requests.exceptions.Timeout`
- `requests.exceptions.ConnectionError`
- `requests.exceptions.ChunkedEncodingError`
- HTTP `429`
- HTTP `500`
- HTTP `502`
- HTTP `503`
- HTTP `504`

不建议重试：

- HTTP `400`
- HTTP `401`
- HTTP `403`
- HTTP `404`
- 高德接口 `status == "0"` 的业务错误；
- 搜索结果为空；
- 景点列表为空。

## 日志策略

第一阶段日志只输出到控制台。

日志级别由环境变量控制：

```env
LOG_LEVEL=INFO
```

默认值为 `INFO`。

日志中记录低风险摘要，不记录：

- 完整 URL；
- API key；
- 完整用户消息；
- 完整第三方响应；
- 过长的工具输出。

建议记录：

- 工具名；
- 目的地；
- 城市编码；
- 半径；
- 页码；
- 是否包含关键字；
- 请求耗时；
- 成功或失败状态；
- 错误码；
- 是否使用降级。

示例：

```text
INFO tool=search_nearby_poi status=success city=0730 radius=5000 page=1 elapsed_ms=842
WARNING tool=get_attractions_information status=fallback destination=福州 source=web_search_fallback elapsed_ms=12130
ERROR tool=route_planning status=failed error=amap_request_timeout retryable=true elapsed_ms=24000
```

## 各工具改造方案

### `tools/locations.py`

目标：稳定地点转坐标工具。

改造点：

- 从 `tools.base` 引入 `ok`、`fail`、HTTP helper 和日志 helper；
- 缺少 `AMAP_API_KEY` 时返回 `fail("missing_amap_api_key", ...)`；
- 请求超时设为 `12s`；
- 网络和超时错误按统一策略重试；
- HTTP 错误返回统一失败结构；
- 高德业务错误返回 `fail("amap_geocode_failed", ...)`；
- 未找到地点返回 `fail("location_not_found", ...)`，不重试；
- 成功时 `data` 保持地点列表，并可加入 `source="amap"`。

### `tools/nearby.py`

目标：稳定周边 POI 搜索工具。

改造点：

- 缺少关键字和类型时属于参数错误，继续抛 `ValueError` 或返回 `fail("invalid_poi_query", ...)` 需要实现时二选一；
- 缺少 `AMAP_API_KEY` 返回失败结构；
- URL 拼接改为 `requests.get(..., params=params)`，避免泄露 key 和参数编码问题；
- 请求超时设为 `12s`；
- 网络和临时服务错误重试 2 次；
- 高德业务错误返回 `fail("amap_nearby_failed", ...)`；
- 空 POI 返回 `fail("nearby_poi_empty", ...)`，不重试；
- 成功时返回 `center_point`、`search_result_count`、`pois`、`source="amap"`。

### `tools/transportation.py`

目标：稳定路线规划工具。

改造点：

- URL 拼接改为 `params`；
- 请求超时设为 `12s`；
- 网络和临时服务错误重试 2 次；
- 高德业务错误返回 `fail("amap_route_failed", ...)`；
- 没有公共交通方案时不视为异常，返回成功数据，但在 `warnings` 中标记；
- 成功时返回路线摘要和 `source="amap"`。

### `tools/web_search.py`

目标：保留当前 3 次搜索重试，同时统一返回结构。

改造点：

- 保留 `max_attempts = 3`；
- 只重试搜索超时、连接错误、搜索服务临时异常；
- 空搜索结果返回 `fail("web_search_empty", ...)`，不重试；
- 搜索失败返回 `fail("web_search_failed", ..., retryable=True/False)`；
- 成功时返回搜索结果列表和 `source="duckduckgo"`。

### `tools/attractions.py`

目标：景点抓取稳定优先，抓取失败时降级搜索。

改造点：

- `MAX_SCENIC_SPOTS` 从 7 改为 5；
- Selenium 抓取失败时不让整体工具失败；
- 捕获页面加载、元素查找、页面结构变化等外部依赖失败；
- 失败时调用 `web_search` 降级搜索；
- 降级结果在 `data` 中标记：
  - `source="web_search_fallback"`；
  - `fallback_used=True`；
  - `warnings` 中说明 Selenium 失败原因摘要；
- 如果 Selenium 成功，返回：
  - `source="mafengwo"`；
  - `fallback_used=False`；
  - `overview`；
  - `scenic_list`。

前端调试面板当前会展示工具输出，因此降级标记会自然出现在 `tool_end` 输出中，不需要改 `/chat/stream` 事件格式。

## Prompt 适配方案

只小幅调整 `prompts/main.py`，不重写大 Prompt。

新增工具返回格式说明：

- 当工具返回 `success=true`，应读取 `data` 中的信息；
- 当工具返回 `success=false`，应读取 `error.message` 和 `error.detail`；
- 不要把失败结果当成真实旅游事实；
- 工具失败后可以换参数重试、使用其他工具降级，或向用户说明信息暂不可用；
- 如果 `data.fallback_used=true`，需要在最终回答中谨慎说明信息来源可能不完整；
- 不要向用户暴露 API key、完整 URL 或内部堆栈。

## 测试方案

新增 `tests/` 目录，只覆盖工具层核心场景。

测试不调用真实外部 API，全部使用 mock。

建议测试文件：

- `tests/test_tools_locations.py`
- `tests/test_tools_nearby.py`
- `tests/test_tools_transportation.py`
- `tests/test_tools_web_search.py`
- `tests/test_tools_attractions.py`
- `tests/test_tools_base.py`

核心覆盖场景：

- 成功返回统一结构；
- 缺少环境变量；
- HTTP 超时；
- 连接错误；
- HTTP 500 后重试成功；
- HTTP 400 不重试；
- 第三方业务错误不重试；
- 空结果不重试；
- JSON 解析失败；
- Selenium 失败后触发 web_search 降级；
- 降级结果包含 `fallback_used=True`。

`pytest` 如果当前环境没有，先作为开发依赖建议，不强制加入 `requirements.txt`。

## 验收标准

第一阶段完成后，应满足以下标准：

- 所有外部工具都返回统一的 `success / data / error` 结构；
- 高德相关请求统一使用 `12s` 超时；
- 网络超时、连接错误、临时服务错误按策略重试；
- 业务错误、空结果、参数错误不盲目重试；
- 工具层不再使用 `print` 输出调试信息；
- 日志输出到控制台，日志级别受 `LOG_LEVEL` 控制；
- 日志不泄露 API key 和完整 URL；
- `tools/attractions.py` 最多抓取 5 个景点；
- Selenium 失败时能降级使用 `web_search`；
- 降级结果中包含 `fallback_used=True` 和 `source="web_search_fallback"`；
- `/chat/stream` 事件格式保持不变；
- 前端调试面板能看到工具失败或降级信息；
- 新增工具层测试，不依赖真实外部 API；
- `new/` 目录未被修改。

## 风险与注意事项

1. 统一返回结构后，模型需要适应从 `data` 中读取业务数据，因此 Prompt 必须同步补充说明。
2. 部分工具原本直接返回列表或字符串，改造后可能影响旧 Prompt 的理解，需要通过手动聊天验证。
3. Selenium 降级搜索得到的信息不一定完整，最终回答中应避免把降级结果说得过于确定。
4. 测试使用 mock 覆盖工具逻辑，但不能替代真实外部 API 联调；真实联调放到后续阶段或手动验证。
5. 第一阶段不修改 `new/`；第三阶段已确认正式入口不依赖它，并完成删除。
